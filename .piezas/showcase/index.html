Is This A Scam

Is This a Scam? lets an older person check a suspicious text, email or link with one big button before they reply or pay. The server masks card, account and verification numbers, runs keyword rules and asks the Claude API for plain-language red flags. The person's adult child (their helper) gets an email, opens the check and answers "Scam" or "All good" in one tap, and the parent's screen shows the answer within seconds. The app never calls a message safe on its own; only the helper can.

Try it yourself: http://localhost:8080 (sample data only)

What it does

  • Only helpers can sign up publicly; there is no public sign-up for parents.
  • A helper signs up with email and password and must set up a second sign-in step (MFA) before using the app.
  • A helper adds their parent with the parent's name and email (and optionally the helper's phone number for a call button), which creates the parent's account and the pair.
  • The helper finishes the parent's first sign-in on the parent's phone, so the parent never types a password: the helper chooses the parent's password when adding them and types it once on the parent's phone, and the parent is never shown it. (Piezas has no passwordless sign-in; option chosen by Taya on 2026-11-06)
  • The parent's sign-in lasts 90 days on their phone.
  • The parent's Home screen has one big "Is this a scam?" button that leads to a screen where they paste the message.
  • Before a message is saved or sent anywhere, card, account and verification numbers in it are masked, keeping only the last four digits (4111 1111 1111 1111 becomes 1111); the full number appears nowhere.
  • Each check gets a risk of red, yellow or green, a list of flags (type, quote, explanation, source), and a one-sentence summary, from keyword rules plus the Claude API.
  • The Claude API is called only from the app's server, with the ANTHROPIC_API_KEY setting, and only ever receives masked text.
  • If the Claude API cannot be reached, the check is still made from the keyword rules alone and is marked rules-only. (confirmed by Taya on 2026-11-06)
  • The result screen shows the risk, the flags in plain language and the summary, then "Waiting for <helper name>".
  • The app never labels a message safe on its own; a check shows "All good" only after the helper answers safe.
  • When a check is created, the helper gets one email with only the parent's name, a plain risk label and a link that needs sign-in; it never contains the message text. The wording follows the template in the group's contracts.md.
  • A helper opens a check from the email link, sees the masked message, risk and flags, and answers "Scam" or "All good" in one tap, with an optional note of up to 200 characters.
  • After answering, the helper sees "Sent. <parent name> sees your answer now."
  • The parent's screen shows the helper's answer within 5 seconds of it being given: "Scam. Don't reply or pay." or "All good."
  • A helper can answer each check only once.
  • If there is no answer after 10 minutes, the parent sees "Don't pay or reply until you talk to someone you trust" with a button to call the helper. Without a helper phone number the button is hidden and the message stays. (confirmed by Taya on 2026-11-06)
  • A parent can create checks and read only their own checks and pair; a helper can read and answer checks only for their own parent; anyone else gets "not found".
  • Every view of a check is recorded in the audit trail with who viewed it and when.
  • Every day at 3:00 a.m. Vancouver time, checks older than 30 days have their masked text cleared, flag quotes and explanations blanked, and any screenshot deleted, with "text cleared at" set; risk, summary and helper answer are kept.
